PAQUETE DE EXPOSICION - EXCEL Y SQL EXTERNOS

No se ejecuta automaticamente. La carga necesita un administrador autorizado,
una instalacion limpia y DEMO_DATA_ENABLED=true. El esquema y el administrador
inicial se crean con Flyway/bootstrap; estos SQL solo agregan datos de ejemplo.

CONFIGURACION DEL SERVIDOR
- En Docker Compose, demo/sql se monta solo para lectura en /app/demo-sql.
  DEMO_SQL_MANIFEST=/app/demo-sql/manifest.properties ya tiene ese valor por defecto.
  Conservar la carpeta demo/sql al actualizar los archivos del despliegue.
  En EC2, desde la carpeta deploy, permitir su lectura al usuario del contenedor:
    chmod 755 ../demo/sql
    chmod 644 ../demo/sql/manifest.properties
  Estos permisos son solo para el manifiesto publico del paquete, nunca para .env.
- En IntelliJ local, agregar DEMO_DATA_ENABLED=true y DEMO_SQL_MANIFEST con la
  ruta absoluta a demo/sql/manifest.properties en esta copia del proyecto.
- Reiniciar el backend al cambiar sus variables de entorno.
- No subir .env ni contrasenas al repositorio.

USO DESDE LA PAGINA
1. Descomprimir el ZIP. Entrar con el administrador y cambiar su clave temporal.
2. Administracion > Preparar demostracion > Cargar datos de demostracion.
3. Seleccionar los 14 Excel 01..14 y los 3 SQL. Se pueden seleccionar juntos si
   estan en la misma carpeta; si estan separados, seleccionar cada grupo y se acumulan.
   No seleccionar manifest.properties, esta guia ni el script de mantenimiento.
4. Pulsar Iniciar carga UNA VEZ. La pagina ejecuta automaticamente:
   00_configuracion_inicial.sql -> Excel 01..09 -> 09_habilitar_matriculas.sql ->
   Excel 10..12 -> 12_escenarios.sql -> Excel 13..14.
5. Revisar el avance. Si falla un paso, corregir la causa y Continuar carga.
   Cada SQL es una transaccion: si falla se revierte entero. Los pasos previos
   confirmados se conservan. Los importadores de Excel mantienen sus reglas normales.
6. Guardar las credenciales generadas como PDF ANTES de cerrar la ventana.
7. Deshabilitar DEMO_DATA_ENABLED cuando ya no se necesite preparar la demo.

SQL EXTERNOS Y SEGURIDAD
Los datos no estan en clases Java ni se incorporan al JAR. El backend valida el
nombre y SHA-256 de cada SQL contra manifest.properties montado en el servidor.
No acepta ejecutar cualquier SQL. Admite SELECT/INSERT/UPDATE, no DDL, DELETE,
procedimientos ni COMMIT. Las referencias se resuelven por documentos/codigos,
sin IDs numericos fijos. No hay passwords en los SQL.
Los parametros :fecha_referencia, :instante_carga y :actor los completa el backend.
Estos archivos estan preparados para el boton, no para pegarlos sin adaptar en Workbench.
Si el equipo edita intencionalmente un SQL, revisarlo y ejecutar actualizar-manifiesto.ps1
ANTES de desplegar. Subir al servidor los mismos SQL y manifiesto del paquete entregado.
No editar un SQL de una etapa ya completada: el sistema no sobrescribe esa carga.

RESTABLECIMIENTO PARA ENSAYO
No borrar tablas ni flyway_schema_history de una base compartida. Crear otro esquema
vacio exclusivo de ensayo, configurar DB_URL para ese esquema y reiniciar con bootstrap.
Flyway crea las tablas; entrar con el nuevo administrador y repetir la carga del paquete.
No basta borrar CargaDemostracion: quedan todas sus relaciones. No se borra S3.
Los adjuntos se suben por el flujo normal; el paquete no fabrica archivos ni claves S3.
El reinicio de la base y el despliegue son pasos distintos: preparar y cronometrar
el arranque de imagenes, migraciones y la carga antes de la presentacion.
